# 数据治理中心 技术架构设计

## 1. 技术路线

结合未来规划：

    数据治理中心
            ↓
    Semantic Package
            ↓
    PI SDK Agent
            ↓
    Query Agent SDK
            ↓
    Eureka

第一阶段只建设数据治理中心。

------------------------------------------------------------------------

# 2. 推荐技术栈

## 前端

    Next.js
    React
    TypeScript
    Tailwind CSS
    shadcn/ui

原因：

-   与Eureka技术栈一致
-   后续Agent产品集成方便

------------------------------------------------------------------------

## 后端

    NestJS
    Prisma
    PostgreSQL

原因：

-   数据治理平台偏业务系统
-   模块结构清晰
-   与前端统一TypeScript生态

------------------------------------------------------------------------

## AI层

第一阶段：

    LLM API

不引入Agent Framework。

后续：

    PI SDK Agent Runtime

------------------------------------------------------------------------

# 3. 项目结构

采用Monorepo：

    data-governance-platform

    ├── apps
    │
    │── web
    │   └── Next.js
    │
    │── api
    │   └── NestJS
    │
    ├── packages
    │
    │── database
    │
    │── types
    │
    └── docs

------------------------------------------------------------------------

# 4. 后端模块

    src/

    ├── datasource
    ├── metadata
    ├── governance
    ├── semantic
    ├── package
    ├── llm
    └── rule

职责：

## metadata

DataWorks同步。

## governance

治理任务流程。

## llm

模型调用和Prompt管理。

## semantic

正式语义资产。

## package

生成Semantic Package。

------------------------------------------------------------------------

# 5. 部署

第一版：

Docker Compose

包含：

    web

    api

    postgres

    nginx

不使用：

-   Kubernetes
-   微服务

------------------------------------------------------------------------

# 6. 开发原则

1.  按Milestone开发。
2.  每阶段完成后验收。
3.  不提前开发Agent能力。
4.  保持模块化，方便未来接入PI SDK。
