# Eureka单位展示核验与需求纠正

## 用户确认后的当前要求

2.4.0时曾按“单位之外还需确认尺度”实现。这与用户要求不一致，不能视为业务效果已完成。现改为仅由已有unit决定：%乘100，万元除10000，亿元除100000000，小数默认2位。治理页面新增的精度/尺度控件、提示和正式配置字段已移除。

当前代码版本：Codex/Claude2.3.1，Eureka2.4.1。实现和部署以 [当前说明](agent-query-quality-implementation.md) 为准，不再要求用户维护或发布额外格式配置。

## 已做过的2.4.0线上核验（历史事实，不代表新版已部署）

用户桌面包 `atlas-ask-eureka-2.4.0-d585b762d8e9.zip` 为2.4.0、11个文件；SHA-256为 `0e10a33d56d0a14595c1d4ed716ebcd9fcb9540b3e9e4c5b1882d42adb1b1c1e`，与当时对话加载包相同。

当时只读取线上MCP正式语义、目录和检索元数据，未调用query_data/get_dimension_values，未执行付费查询。确认：

- 线上10个工具已有新版wait_ms参数与有界等待描述。
- 正式“天猫指标销售分析表”的推广点击率/加购率unit为%，因此按用户现要求就应直接换算；之前额外要求维护尺度是实现设计错误。
- 线上搜索有3个FULL匹配推广来源，已返回用途、粒度、公式及source_resolution。上下文不足时应先让用户选择；没有原会话完整记录，不能断言模型本次已执行选择。
- 线上Web公开JS当时有新增格式控件；本轮源码已删除，仍需部署Web才能从用户页面移除。
- 16表目录返回轻量字段，核验会话ID和revision在读取前后不变。这不是实际源查询速度或真实澄清恢复的验收。

## 本轮回归

共享库验证unit直接换算、百分比/万元/亿元、精度/null/ID及原始行不变；API验证Package只维护unit且单位变化不改SQL；Web验证表格与MCP一致、治理无新增格式控件、图表轴值和精确提示按相同单位换算。

本轮没有修改线上正式语义，也没有自动部署。单纯更新ZIP不能更新API/Web或数据库结构。原管理员自定义模板仍需避免旧格式规则与当前单位约定冲突，不自动覆盖其中业务约束。
